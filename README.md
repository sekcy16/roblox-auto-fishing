# โปรแกรมตกปลาอัตโนมัติ Roblox

เวอร์ชันปัจจุบัน: **0.0.6**

ดาวน์โหลดสำหรับ Windows และ Linux: [GitHub Releases](https://github.com/sekcy16/roblox-auto-fishing/releases/latest)

โปรแกรมอ่านภาพหน้าจอและกดเมาส์ซ้ายเพื่อให้ตัวเลื่อนสีขาวอยู่ในช่องม่วง โดยแยก UI และความสามารถตามระบบปฏิบัติการอย่างชัดเจน:
- **Linux (X11):** รองรับทั้ง **โหมดปกติ (จอเดี่ยว)** และ **โหมดจอแยก 2 จอ (Gamescope + Sober)** ผู้ใช้สามารถทำงานหรือใช้งานเมาส์บนจอ 2 ได้โดยไม่ถูกรบกวน
- **Windows:** รองรับเฉพาะ **โหมดปกติ (จอเดี่ยว)** โดยต้องเปิดหน้าต่าง Roblox ค้างไว้ด้านหน้าและบอทจะควบคุมเมาส์ร่วมกับผู้ใช้ *(รุ่นปัจจุบันยังไม่รองรับโหมดสองจอบน Windows)*

## ความสามารถและการเปิดโปรแกรมตามระบบปฏิบัติการ

### Linux
- **ตัวเปิดใช้งาน:** `./run.sh` (เปิด Linux UI ผ่าน `ui_linux.py` โดยตรง)
- **โหมด Desktop X11:** โหมดมาตรฐานสำหรับจอเดี่ยว เลือกหน้าต่างเกมและควบคุมเมาส์
- **โหมด Gamescope สองจอ (Gamescope + Sober):**
  - แสดงปุ่ม **เปิด Sober ใน Gamescope** และปุ่ม **ตรวจสถานะ Gamescope**
  - มีระบบตรวจจับ Sober เดิมเพื่อป้องกันการเปิดซ้ำ
  - ค้นหา DISPLAY ภายในอัตโนมัติ ไม่ hardcode พิกัดหรือหมายเลขจอ
  - กำหนดอัตรารีเฟรชทั้ง `-r 60` และ `-o 60` พร้อมคงการเลือก GPU อัตโนมัติเพื่อความเสถียร
  - Worker ทำงานและส่งเมาส์ภายในหน้าจอ Gamescope เท่านั้น ไม่รบกวนจอจริงของผู้ใช้
  - เมื่อเกมปิด จับภาพล้มเหลว หรือกด F8 ระบบจะปล่อยเมาส์และหยุดอย่างปลอดภัยทันที

### Windows
- **ตัวเปิดใช้งาน:** `RobloxAutoFishing-v0.0.6.exe` (หรือ `python ui_windows.py`)
- **โหมดปกติเท่านั้น:** แสดงเฉพาะตัวเลือกหน้าต่าง Roblox, พื้นที่ตรวจจับ และปุ่มเริ่ม/หยุด
- **ไม่มี UI เฉพาะ Linux:** ไม่แสดงปุ่ม Gamescope, Sober, X11 หรือ DISPLAY ใดๆ บน Windows
- **สถานะสองจอบน Windows:** กำลังศึกษาความเป็นไปได้ (feasibility study) ด้วย Windows Graphics Capture แต่ยังไม่เปิดใช้งานในรุ่นนี้ เนื่องจากต้องพิสูจน์การรับอินพุตเบื้องหลังของ Roblox โดยไม่ใช้ `SendInput`

### การรัน Python ส่วนกลาง
- การรัน `python auto_fishing.py` จะตรวจสอบระบบผ่าน `platform.system()` และเลือก UI ของระบบนั้นๆ โดยอัตโนมัติ
- ใช้แกนตรวจจับภาพ (`detect_bar`, `detect_bite`), ฟิสิกส์และการเคลื่อนที่ (`Controller`, `choose_hold`), settings validation และลูปการตกปลาร่วมกัน
- แยก namespace การตั้งค่าใน `settings.json` (`settings["linux"]` และ `settings["windows"]`) ทำให้พิกัด ROI ของแต่ละระบบและแต่ละโหมดไม่ทับซ้อนกัน

กด **หยุด** เพื่อยกเลิกการนับถอยหลังหรือหยุดการทำงาน กด **F8** เพื่อหยุดทันทีขณะระบบทำงาน เมื่อสลับออกจากเกมหรืออ่านภาพไม่ชัด โปรแกรมจะปล่อยเมาส์และพักการทำงาน ต้องกดเริ่มใหม่ด้วยตัวเอง

## ขั้นตอนการทำงานของระบบ

- **เริ่มรอบ:** เหวี่ยงเบ็ดตามเวลากดค้างที่ตั้งไว้ (`cast_seconds`)
- **รอเริ่มมินิเกม:** โหมดเบ็ดตกปลาสามารถตรวจสัญญาณจาก ROI bite เทียบกับ `bite-template.png` หากตั้งค่าไว้ ส่วนโหมดแหจะรอแถบมินิเกมโดยตรง ระบบจะรอต่อไปโดยไม่เหวี่ยงซ้ำและไม่มี timeout
- **ตรวจพบปลา:** เมื่อพบสัญญาณปลากินเบ็ดต่อเนื่องครบ 3 เฟรมขึ้นไป ระบบจะคลิก 1 ครั้งเพื่อดึงปลา แล้วรอแถบมินิเกม (หากสัญญาณหายไป 3 เฟรมจะปลด latch ให้ตรวจจับรอบใหม่ได้)
- **เข้าสู่โหมดควบคุม (Track):** เมื่อพบแถบมินิเกมที่ถูกต้อง (`valid`) ระบบจะเข้าสู่โหมดควบคุมและส่งคำสั่งกดหรือปล่อยเมาส์ทันทีตั้งแต่เฟรมแรก เพื่อให้การตอบสนองรวดเร็วทั้งเบ็ดตกปลาและแห
- **จบรอบ:** เมื่อแถบมินิเกมหายต่อเนื่องครบ 1.0 วินาที ระบบจะถือว่าจบเกมและเริ่มเหวี่ยงเบ็ดรอบถัดไป

## ตัวเลือกและอุปกรณ์ตกปลา

- **ประเภทอุปกรณ์ตกปลา:**
  - **เบ็ดตกปลา:** เบ็ดตกปลา — โดยทั่วไปปลากินภายในประมาณ 30 วินาที
  - **แห:** แห — อาจใช้เวลารอประมาณ 30–60 วินาที และช่วงดึงปลาอาจนานกว่า
  - *หมายเหตุ:* ตัวเลือกนี้มีไว้สำหรับแสดงชื่อโหมดและข้อความแนะนำใน UI เท่านั้น ระบบไม่ได้ใช้เวลา 30–60 วินาทีเป็นเงื่อนไขหน่วงเวลา และไม่มีการใช้ timeout ตัดการทำงาน
- **พื้นที่สัญญาณปลากินเบ็ด (จำเป็น):** พื้นที่บริเวณที่มีไอคอนแจ้งเตือนปลากินเบ็ดปรากฏ
- **ภาพตัวอย่างสัญญาณ (ตัวเลือกเสริม):** ใช้คู่กับพื้นที่สัญญาณปลากินเบ็ดในโหมดเบ็ดตกปลา ครอบไอคอนให้พอดีและมีขนาดไม่เกินพื้นที่ค้นหา โปรแกรมบันทึกเป็น `bite-template.png`
- **ตั้งค่าละเอียด:** ปรับระยะเผื่อกลางช่องม่วง เวลาชดเชยการเคลื่อนที่ ความเข้มงวดในการตรวจจับสัญญาณภาพ และการคลิกยืนยันเมื่อปลากินเบ็ด

## ติดตั้งบนเครื่องอื่น

ใช้ Python ที่มี Tkinter และติดตั้งไลบรารีภายในโฟลเดอร์โปรเจกต์

Linux X11:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python auto_fishing.py
```

Windows PowerShell:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe auto_fishing.py
```

## สร้างไฟล์ส่งให้ผู้ใช้ Windows

คัดลอกโปรเจกต์ไปยังเครื่อง Windows ที่ติดตั้ง Python 3.12 แล้วดับเบิลคลิก `build-windows.bat` เมื่อการทดสอบและ Build ผ่าน ไฟล์พร้อมส่งจะอยู่ที่:

```text
release\RobloxAutoFishing-v0.0.6-Windows.zip
```

ผู้รับแตก ZIP แล้วเปิด `RobloxAutoFishing-v0.0.6.exe` ได้ทันทีโดยไม่ต้องติดตั้ง Python ค่าตั้งและภาพสัญญาณของผู้ใช้ Windows จะอยู่ใน `%LOCALAPPDATA%\RobloxAutoFishing`

Windows ให้เลือกติดตั้ง Tcl/Tk ในตัวติดตั้ง Python ส่วน Linux ใช้แพ็กเกจ Tk ของดิสโทร รุ่นนี้ไม่รองรับ Wayland และกำหนดพื้นที่ได้เฉพาะจอหลัก

## ผลตรวจสอบล่าสุด

- ชุดทดสอบอัตโนมัติ 40 รายการผ่าน โดยไม่ส่งคำสั่งเข้าเกม
- X11: เปิดหน้าต่าง จับภาพ อ่านโฟกัส กด/ปล่อยเมาส์ในหน้าต่างทดสอบ และปุ่ม F8 ผ่านการตรวจจริง
- ตรวจภาพหน้าหลักภาษาไทยและหน้าตั้งค่าละเอียดบนจอ 1920×1080 แล้ว ปุ่ม ช่องกรอก และช่องสถานะแสดงครบ
- Windows และความแม่นยำในการตกปลาจริงยังไม่ได้ทดสอบ ต้องตั้งพื้นที่และปรับค่าจากการเล่นจริงก่อนประเมินผล

```bash
.venv/bin/python -m unittest test_auto_fishing -v
./run.sh --replay tests/fixtures
```

ภาพแนบเป็นภาพนิ่ง การตรวจภาพย้อนหลังนี้ไม่ได้ยืนยันความแม่นยำของการติดตามขณะเคลื่อนที่

## การแก้ตัวตรวจแถบจากเกมจริง

แก้การหาแถบดำที่สับสนกับฉากกลางคืน และช่วงสีม่วงที่แคบเกินไป เปลี่ยนเป็นตรวจสี HSV ร่วมกับรูปทรงช่องม่วงและตัวเลื่อนสีขาวที่อยู่แนวเดียวกัน ทดสอบภาพจริงทั้งกลางวันและกลางคืน และอ่านแถบจากเกมสดแบบไม่ส่ง input ได้ต่อเนื่อง 20 เฟรม การตรวจนี้ยืนยันการอ่านตำแหน่ง ไม่ใช่อัตราจับปลาสำเร็จ

แก้บั๊กหน้าต่างเลือกพื้นที่เปิดซ้ำไม่ได้หลังปิดด้วย X แล้ว ตรวจการเปิดซ้ำและลากกรอบผ่านหน้าต่างจริงบน X11 แล้ว
